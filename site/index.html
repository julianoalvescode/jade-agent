Features

Five pillars.
Every change.

Each change is checked against the same five pillars, scaled to its risk. When they conflict: security, correctness, accessibility, performance, then taste.

  1. #1 Build

    Quality

    Readable, typed code. Tests that check behavior, not internals. A code review before every delivery.

  2. #2 Grow

    Scalability

    No fragile local state. Pagination, limits, idempotent writes, queues and cache with a clear invalidation rule.

  3. #3 Guard

    Security

    Validation and authorization on the server. OWASP checks at every changed boundary: BOLA/IDOR, XSS, injection, SSRF, secrets.

  4. #4 Speed

    Performance

    Measure before optimizing. Web Vitals on the front end. No N+1, missing indexes or heavy work inside a request.

  5. #5 Craft

    UI/UX

    Design-system reuse, a strict 8-point grid, loading/empty/error states and WCAG 2.2 AA accessibility.

  6. #6 Spec

    OpenSpec, always

    Every invocation runs inside OpenSpec. The spec says what to build. Jade’s skills decide how.

Spec-driven

Agree first.
Then build.

Questions use explore. Any code change, even a small fix, gets an OpenSpec change. A task is ticked only when its evidence exists.

  1. 01

    Explore

    Reads the repo and weighs options on the five pillars. No code.

  2. 02

    Propose

    Writes proposal, delta specs, design (one line per pillar) and tasks.

  3. 03

    Apply

    Builds task by task with the right skills: front end, back end, Figma, contract.

  4. 04

    Verify

    Runs the quality gate against every requirement and scenario.

  5. 05

    Archive

    Only when the gate is READY and you agree. Specs absorb what shipped.

Delivery

No proof,
no “done”.

Every task ends with a matrix: criterion → implementation → evidence → state. Jade keeps code written, validated, PR open, merged and deployed apart.

  • PASS Checked, with concrete evidence.
  • FAIL Checked, and the requirement broke.
  • BLOCKED Access, data or a decision is missing.
  • NOT RUN Relevant, not run. Reason and risk stated.
  • N/A The change does not touch it.

Install

Two minutes
to start.

Needs Python 3.10+ and Git. Node is only needed for the OpenSpec CLI.

  1. Install Jade into your project

    git clone https://github.com/julianoalvescode/jade-agent.git
bash jade-agent/scripts/install-skills.sh claude-code --project /path/to/project

    Add --core-only for the eight Jade skills without network, or --replace to update with a backup in .jade/backups/.

  2. Set up OpenSpec

    npm install -g @fission-ai/openspec@latest
cd /path/to/project && openspec init

  3. Connect your tools

    claude mcp add --transport http atlassian https://mcp.atlassian.com/v2/mcp
claude mcp add --transport http figma https://mcp.figma.com/mcp

    Finish OAuth in /mcp. Copy jade.project.example.json to jade.project.json and fill in only what you know.

  4. Ask Jade

    Use the Jade agent to implement ticket PROJ-123. Read the linked documents, check the back-end contract and validate the criteria. Prepare the PR with the evidence.

FAQ

Questions

Does Jade change my back end?

Only when the back end is part of the request. Infrastructure, permissions, shared databases and deploys always need an explicit request.

What if the OpenSpec CLI is not installed?

Jade asks you once to install it. Meanwhile she writes the change artifacts by hand in the same folder structure and marks openspec validate as NOT RUN.

Will it overwrite my CLAUDE.md, AGENTS.md or .mcp.json?

No. The installer reports conflicts before writing. With --replace it keeps a backup of every file it changes.

What happens without Figma access?

The visual step is marked BLOCKED. Jade does not recreate a screen from memory. Work that does not depend on the design can continue.

Are the community skills trusted?

Each one is pinned to an exact commit and checked by name. The installer never runs third-party scripts. Pinning gives traceability; it is not a security audit.
